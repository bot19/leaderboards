# 1.5.1: Confirmation window of 30 minutes

Implement this by following `docs/agents/build-docs.md`.

**Version:** 1.5.1

**Status:** resolved

**What to build:** A Pending Match that nobody on the opposing Side responds to becomes Confirmed on its own **30 minutes** after it was recorded, instead of 48 hours. No UI change: the Confirmation window is only read by auto-confirm.

**food-friends reference:** None

**Schema:** One migration that replaces `public.rating_constants()` so it returns `confirmation_window_minutes integer` (value `30`) instead of `confirmation_window_hours`, and updates `private.confirm_expired_pending_matches` to expire Pending Matches with `make_interval(mins => …)` from that constant. Keep the other rating constants unchanged. The pg_cron job stays as it is (still calls the same function every minute). Recreate the `leaderboard` view in that migration (it depends on `rating_constants()`). Update `supabase/seed.sql` so the two seeded Pending Matches sit inside the new window (a few minutes ago), so they stay Pending after reset.

- [x] `package.json` version is `1.5.1`
- [x] `rating_constants()` exposes `confirmation_window_minutes` as `30`, and no longer exposes `confirmation_window_hours`
- [x] A Pending Match recorded less than 30 minutes ago stays Pending when auto-confirm runs
- [x] A Pending Match recorded 30 minutes or more ago becomes Confirmed and rated, with `confirmed_at` at recorded time plus the window
- [x] Integration tests pin the constant and the inside-window / expired behaviour in minutes
- [x] Seeded Pending Matches still show as Waiting for you after a reset

**Out of scope:** showing the Confirmation window in the UI; making it configurable per Ladder; changing the cron schedule.
