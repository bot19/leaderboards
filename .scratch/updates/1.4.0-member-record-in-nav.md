# 1.4.0: Show a Ladder member's record in the nav drawer

Implement this by following `docs/agents/build-docs.md`.

**Version:** 1.4.0

**Status:** resolved

**Blocked by:** 1.2.0 (Ladders list in the drawer's menu view) and 1.3.0 (bottom nav bar).

**What to build:** Tapping a Ladder member's name on the Ladder page opens the nav drawer on a **member view** instead of going to a separate page. This works for any Ladder member, including yourself. The view shows a summary of their record on that Ladder, then their Matches. The page at `/ladders/$ladderId/members/$memberId` is removed.

**food-friends reference** (all paths under `/Users/teex/Code/food-friends/`):

| Take | From |
|---|---|
| A person's view rendered inside `NavDrawer`, opened by a search param; title is their name; skeleton while loading; not-found message | `src/components/user/UserPanel.tsx` |
| Body layout and the drawer actions (Nav, Close) at the bottom | `src/components/user/UserProfilePanel.tsx` (already copied here as `src/components/nav/NavDrawerActions.tsx`) |
| A search param that opens the panel and is cleared on close | `src/lib/mapSearch.ts` (`user`) |

**Schema:** One migration, read-only:

- Add `public.ladder_member_record(p_ladder_member_id uuid)`. It returns a single row computed over **all** of that Ladder member's Confirmed Matches on the Ladder, not only the page the app has loaded. Order by confirmation, as Ratings are (ADR-0002).

  | Column | Meaning |
  |---|---|
  | `wins`, `losses`, `draws` | Counts across their Confirmed Matches |
  | `form` | Their last 5 results, newest first, as `text[]` of `'W'`, `'L'` or `'D'` |
  | `streak_result`, `streak_length` | Their current run of the same result, for example `'W'` and 3. Null and 0 when they have no Confirmed Matches |
  | `peak_rating`, `peak_at` | Their highest Rating after any Confirmed Match (Rating before + change), and when that Match was Confirmed. Null when they have none |

- A Replay rewrites the stored Rating changes, so every value is read fresh from the current rows.
- Make it `security invoker`, so the existing row-level security decides who can see it. Grant it to `authenticated`.
- Regenerate `src/types/db.ts`.

### Opening it

- Add `'member'` to `navViews` in `src/features/nav/navSearch.ts`, and add an optional `member` search param holding the Ladder member's id, on the root route next to `nav`.
- In `LeaderboardPanel.tsx` (Leaderboard rows and the Inactive list) and `MembersPanel.tsx`, member names stop linking to the old route. They set `nav: 'member', member: <id>` and keep `tab`, so closing the drawer returns to the same tab.
- Both `nav` and `member` live in the URL, so the browser's Back button closes the view and a reload reopens it.
- Closing the drawer clears both params. Its **Nav** action switches to the menu view and clears `member`.
- The Profile button on the bottom bar still opens the profile view (display name) unchanged.

### The member view

Render it inside `SignedInChrome`'s `NavDrawer`, next to the existing menu and profile views.

- **Title:** the Ladder member's display name, with `NavDrawer`'s subtitle set to the Ladder's name.
- **Summary**, one compact block at the top:
  - **Rating:** shown with `formatRating`, with `Provisional` after it when that applies.
  - **Rank:** taken from `listLeaderboard`, for example `#3 of 12`. Inactive, Left and Removed members have no rank, so show `Inactive`, `Left` or `Removed` in its place.
  - **Record:** `12W · 5L · 1D`, from `ladder_member_record`. Leave out `D` when it's 0 and the Game doesn't allow Draws.
  - **Form:** their last 5 results as small dots, newest on the left (green for W, red for L, neutral for D). Give the group an `aria-label` that reads out the results, for example `Last 5: won, won, lost, won, drew`. Add `Streak W3` after the dots, coloured by result. Hide the streak when it's under 2.
  - **Peak:** `Peak 1548 · 12 Oct`, using `formatRating` and the relative time from 1.1.0. Hide it with no Confirmed Matches.
- **Matches:** below the summary, the Ladder member's Confirmed and Pending Matches, newest first. Leave out Voided and Rejected ones, since they aren't part of a record.
  - Show each as a **member-perspective row** (see below), not the neutral 1.1.0 card.
  - Use 1.1.0's paging: 10 per page, `Showing n of total Matches`, and the load-more button.
  - Add a paged read to `src/data/match.ts` filtered to Matches this Ladder member took part in, with status Confirmed or Pending. For example, use an inner-joined, aliased `participants` embed to filter, while still embedding every Participant. Return the total count too.
- **Empty:** `No Matches yet.`
- **Loading:** the repo's `Skeleton` while loading, as in food-friends' `UserPanelSkeleton`.
- **Not found:** if the id is unknown or not visible, show `This Ladder member is not available.`
- **Bottom:** `NavDrawerActions` (Nav, Close).
- The view needs the Ladder member's `ladder_id`, so fetch the member by id. It doesn't rely on the current route.

### Member-perspective row

Each row tells the Match from the viewed Ladder member's side. Reuse 1.1.0's pieces: the status card styles and icons from `MatchCard.tsx`, `formatRelativeTime` with the `<time>` title, `formatRating` and `formatRatingChange`, and the green and red classes. Put shared bits, such as the outcome colours, in one place that `MatchCard` and this row both import, rather than copying them.

```
● Won  vs Priya                 +12.4
  1v1 · 3d ago            1512 → 1524
● Lost vs Dave & Kim             −8.1
  2v2 with Sam · 5d ago   1520 → 1512
```

- **First line:**
  - The outcome: `Won`, `Lost` or `Drew`, coloured `text-green-700`, `text-red-700` or neutral.
  - Then `vs <opponents' names>`, joined with ` & `.
  - Their Rating change on the right, in the same colour.
- **Second line**, low-key (`text-xs text-neutral-500`):
  - The format, `1v1` or `2v2`, taken from the Side size.
  - `with <partner>` when their Side has more than one Participant.
  - The relative time: Confirmed time for Confirmed Matches, Recorded time for Pending ones.
  - On the right, `<Rating before> → <Rating after>`.
- **Pending rows:**
  - Use the Pending card style, `IconClock` and the `Pending` label.
  - Read the outcome as recorded: `Won`, `Lost` or `Drew`.
  - No Rating change and no before → after, since nothing has moved yet.
- Names truncate at 300px. The Rating change and the before → after never wrap or get cut off.
- Put the outcome logic (which Side they were on, their result, opponents, partner, format) in a pure function in `src/features/matches/`, unit-tested on its own.

### Removing the page

- Delete `src/routes/ladders/$ladderId_.members.$memberId.tsx` and let the route tree regenerate.
- Remove `listRatingHistory` and its type if nothing else uses them. The member-perspective rows now show the before → after Rating.
- Don't add a redirect. The route was only ever linked from inside the app.
