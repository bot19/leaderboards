# 1.3.0: Move the side rail to a bottom nav bar

Implement this by following `docs/agents/build-docs.md`.

**Version:** 1.3.0

**Status:** ready-for-agent

**Blocked by:** 1.2.0, which removes the rail's Home button. Build on whatever buttons the rail has once 1.2.0 is in.

**What to build:** The right-edge side rail covers the right of the page, where Leaderboard Ratings sit. Replace it with a floating bar centred at the bottom of the screen, as in food-friends. It holds the same buttons in the same order, reading left to right instead of top to bottom, so the human can rearrange them after review. It appears wherever `SignedInChrome` renders today: `/`, `/ladders/$ladderId`, the Ladder member page and `/join/<code>`. The User avatar on it shows both initials in full.

**food-friends reference** (all paths under `/Users/teex/Code/food-friends/`):

| Take | From |
|---|---|
| The bar: fixed at the bottom, `px-4 pb-[max(1rem,env(safe-area-inset-bottom))]`, inner `rounded-2xl bg-white/95 px-5 py-3 shadow-lg backdrop-blur`, buttons spread with `justify-between`, full width on mobile, `sm:w-max sm:min-w-[22rem]` on desktop, `aria-label="Primary"` | `src/components/nav/MapNavBar.tsx` |
| `isActive` on the button whose panel is open | `MapNavBar.tsx` (Nav uses `isNavOpen`) |

`MapNavBar` uses `absolute` because it sits over a map. Here the bar is `fixed` to the viewport, as `SideRail` is.

**Schema:** None.

### The bar

- Replace `src/components/nav/SideRail.tsx` with `src/components/nav/BottomNavBar.tsx`. Start it with a provenance line copied from `MapNavBar.tsx`, saying what changed. Its buttons are children, as they are with `SideRail`, and it stays at `z-30`. That keeps it under Record Match (`z-40`) and the nav drawer (`z-50`).
- In `SignedInChrome`, rename the `railBeforeNav` prop to `barBeforeNav` and update its callers. The button order doesn't change: Profile avatar, then the page's buttons (Record a Match on the Ladder page), then Nav.
- Every button keeps its current `aria-label`, icon, style and click behaviour. Nav gets `isActive` while the drawer's menu view is open, and Profile while its profile view is open. That's the only change to how the buttons look.
- Delete `SideRail.tsx` once nothing imports it.

### Page padding

The bar floats over the bottom of the page, so content mustn't end up hidden behind it.

- Each `<main>` that renders `SignedInChrome` gets enough bottom padding for the last row (the last Leaderboard row, the Matches load-more button, the Members list) to scroll fully clear of the bar. That's roughly the bar's height plus its gap plus `env(safe-area-inset-bottom)`.
- Write the padding once, as a shared class or constant next to `BottomNavBar`, and use it in all four routes. Don't hand-tune it per page.
### Avatar initials

On the rail, the Profile avatar crops its two letters: Fraunces initials such as `MW` overflow the 40px box.

- Both letters must be fully visible, with clear space on each side, for wide pairs (`MW`, `WM`, `WW`) as well as narrow ones (`IL`).
- First, try keeping the 40px square and shrinking the letters (for example `text-xs`, or loosening `tracking-tight`).
- If that drops below about 12px, let the avatar grow sideways instead (`h-10 min-w-10 px-1.5`), so it may be slightly rectangular.
- Change only the bar's avatar, through `UserAvatar`'s `className`. Leave the default size used elsewhere (for example `NavProfile`) as it is.
