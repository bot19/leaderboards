# 1.2.0: Open on the Default Ladder

Implement this by following `docs/agents/build-docs.md`.

**Version:** 1.2.0

**Status:** resolved

**What to build:** Each User can have a **Default Ladder**, stored on their profile. Signing in, or opening `/`, takes them straight to that Ladder's Leaderboard. The list of Ladders moves into the nav drawer, where they can open any Ladder, join one by Join code, create one, and star the Ladder they want as their default. `/` shows that list only when the User has no Default Ladder, which happens when they have no Ladders, or have two or more and haven't picked one.

**Schema:** One migration. Every write goes through a database function (ADR-0003).

- `profiles.default_ladder_id uuid null references ladders (id) on delete set null`.
- **The rule:** a User's Default Ladder is always a Ladder they're Joined to. If they have no Default Ladder and exactly one Joined Ladder, that Ladder becomes their default. Put this in a single helper, `private.settle_default_ladder(p_user_id uuid)`:
  1. Set `default_ladder_id` to null if the User isn't Joined to that Ladder.
  2. If it's then null and the User has exactly one Joined Ladder, set it to that Ladder.
- `public.set_default_ladder(p_ladder_id uuid)`: the caller must be Joined to the Ladder, or it raises. Sets the caller's default. Grant to `authenticated` only.
- `create_ladder` and `join_ladder` gain `p_make_default boolean default false`. When it's true, set the new Ladder as the caller's default. Then call `settle_default_ladder` either way. Drop the old signatures rather than adding overloads, so PostgREST doesn't see two candidates. Keep the grants as they are.
- `leave_ladder`, `remove_ladder_member` and `reinstate_ladder_member` call `settle_default_ladder` for the affected User. `delete_ladder` calls it for every User who was a member, after the delete. The foreign key has already nulled their default by then.
- Backfill: run `settle_default_ladder` for every profile. Users with one Ladder get it as their default. Users with two or more keep null and pick from the list.
- Regenerate `src/types/db.ts`. Add `defaultLadderId: string | null` to `Profile` in `src/data/profile.ts` and to its select.

### Glossary

Add **Default Ladder** to `GLOSSARY.md` under People and membership: the Ladder a User opens on when they sign in. It's always one they're Joined to. Their only Ladder becomes it automatically, and they can move it to another Ladder but not clear it. _Avoid_: home Ladder, main Ladder, favourite.

### `/`

- In `beforeLoad`, if `profile.defaultLadderId` is set, redirect with `replace` to `/ladders/$ladderId` with `tab: 'leaderboard'`. Login, onboarding and auth callback already land on `/`, so they all open the Default Ladder without any change of their own. A `redirect` search param (for example back to `/join/<code>`) still wins, as it does now.
- With no Default Ladder, `/` renders the Ladders section (below) as it does today.

### Ladders section

Pull the heading, the Join a Ladder and New Ladder IconButtons with their forms, and the list out of `src/routes/index.tsx` into one component, `src/features/ladders/LaddersSection.tsx`. `/` and the drawer both render it.

- **Star:** each row starts with a star IconButton (44px tap target).
  - The Default Ladder shows `IconStarFilled` in `text-primary`, with `aria-pressed="true"` and `aria-label="<name> is your Default Ladder"`. Tapping it does nothing, because a Default Ladder can be moved but not cleared.
  - Other rows show `IconStar` with `aria-label="Make <name> your Default Ladder"`. Tapping calls `set_default_ladder`, shows a spinner in place of the star while it's in flight, then refreshes the profile. No success toast. On error, a persistent toast with `id: 'default-ladder'`.
- The rest of the row is the existing link (name on the left, Game on the right), and it truncates at 300px.
- **"Make this my Default Ladder" checkbox:** add it to the Join form and the New Ladder form, above the submit. Show it only when the User already has at least one Joined Ladder. It starts unchecked and passes `p_make_default`. With no Ladders yet there's no checkbox, because the first Ladder becomes the default anyway.
- After a create, join or star, refresh both `['my-ladders']` and the profile (`refreshProfile`).
- **No Ladders:** replace `No Ladders yet.` with:
  - the line `Join a Ladder with a code from a friend, or start your own.`
  - two full-width buttons below it, `Join with a code` (`IconKey`) and `New Ladder` (`IconPlus`), each at least 44px tall
  - The buttons open the same forms as the heading's IconButtons, sharing the same open-form state. The block hides while a form is open.
- **2+ Ladders and no Default Ladder:** above the list, show an `InfoBox` (`info`) with `Star a Ladder to open it when you sign in.` Nothing is picked automatically.
