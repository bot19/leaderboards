# 0.3.0: Home UI and side menu

**Version:** 0.3.0

**Status:** resolved

**What to build:** Every signed-in screen gets a floating side rail on the right edge with two buttons: the User's avatar and a Nav button. Nav opens a drawer that slides in from the right, copied from food-friends. The drawer has a root **menu view** and a **profile view** where the User changes their display name. The Home screen loses its avatar, display name form and Sign out link (all now in the drawer), its top spacing is halved, and creating a Ladder moves behind a `+` button on the **Your Ladders** heading. Every text input in the app gets a white background.

Signed-in screens: `/`, `/ladders/$ladderId`, `/ladders/$ladderId/members/$memberId`, `/join/$token`. Login, signup, onboarding and the auth callback get no rail.

### Decisions already made

- **Drawer state lives in the URL** as an optional `nav` search param (`menu` | `profile`), declared on the root route so every screen keeps it. Back closes the drawer, a refresh keeps it open, and opening or closing keeps the screen's other search params (e.g. the Ladder page's `tab`). This follows food-friends' routed `/nav` and `/user/$userId`.
- **The rail is composable.** It takes its buttons as children, so a later version can show or hide buttons per screen. For 0.3.0 every signed-in screen shows the same two buttons. Each signed-in route renders the rail and drawer itself (one shared component); no route-tree restructure.
- **The drawer is `fixed`, not `absolute`.** food-friends mounts it inside the map. It looks and behaves the same at every width: 300px up to desktop.
- **The rail sits on the viewport's right edge** at every width (`fixed`), over page content, below the drawer and any open panel such as Record Match. It overlapping the right side of the content column is expected.
- **The menu view's middle is blank.** It will hold the User's Match history in a later version. Render an empty flex spacer with no placeholder text.
- **The profile card's second line** is the User's Ladder count ("3 Ladders", "1 Ladder") from the existing `['my-ladders']` query, or "Ladders" while it loads.

### Rail

1. Avatar button: `UserAvatar` of the User's display name, `aria-label="Profile"`. Opens the drawer on the profile view.
2. Nav button: `IconMenu2`, `aria-label="Nav"`. Opens the drawer on the menu view.

### Drawer: menu view

- Header: BrandLockup ("Leaderboards", "Over 9000?!") with the version superscript, then Refresh (invalidates every query and refreshes the profile, spinning while it runs) and Close.
- Body: blank.
- Footer: the profile card (opens the profile view), then Sign out (signs out, then goes to `/login`, as Home does today) and Close.

### Drawer: profile view

- Header: the display name as the title, no tagline, no version, Close.
- Body: the display name form moved from Home (label, input, inline error, **Save display name** button with an in-button spinner, success toast).
- Footer: Nav (back to the menu view) and Close.

### Home

- Header: just `<h1>Home</h1>`.
- Top padding halved: `py-10` becomes `pt-5 pb-10` on Home's `<main>`.
- **Your Ladders** heading row: heading on the left, an IconButton on the right. Closed it shows `IconPlus` with `aria-label="New Ladder"`; open it shows `IconX` with `aria-label="Close new Ladder"`.
- Open: the existing New Ladder form appears between the heading and the Ladder list, focused on its input, followed by a divider line (`<hr>`, neutral-200) before the list. Submitting behaves as today.
- Removed from Home: the avatar and display name subtitle, the display name form, the Sign out link.

### Inputs

Give text inputs, selects and textareas a white background once, in `src/index.css`'s base layer, so every form in the app matches.
