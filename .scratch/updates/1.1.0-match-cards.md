### One Match card

Make a single Match card component, used by both the **Matches** tab and **Waiting for you**, so a Pending Match looks the same in both places.

Top to bottom:

1. **Heading row.** `Alex & Sam vs Priya & Dave` on the left (`min-w-0`, wraps), and the status on the right (`shrink-0`): icon, then label.
2. **Date line.** Low-key (`text-xs text-neutral-500`): `Recorded by Alex · 2h ago`. The time is a `<time dateTime={recordedAt}>` whose `title` is the full local date and time. If the recorder isn't a Participant, take their name from the Ladder's members. If no name can be found, show just the time.
3. **Result line.** The winning Side's names: `Alex & Sam won`. A Draw reads `Draw`. Notes follow as they do now: `Alex & Sam won · best of 3`. Never show "Side A" or "Side B" anywhere in the UI. The `result` values `side_a_won` and `side_b_won` stay as they are in code.
4. **Rating changes** (Confirmed only, as now). Each Participant's name and Rating change. Winners' rows are `text-green-700`, losers' rows `text-red-700`, and a Draw stays neutral.
5. **Actions.** **Void** (History, Admins) or **Reject** and **Confirm** (Waiting for you), unchanged in behaviour and confirmation.

### Status styles

| Status | Card | Icon (Tabler) | Label |
|---|---|---|---|
| Pending | Whole card in InfoBox `warning` colours: `border border-orange-200 bg-orange-50`, label `text-orange-900` | `IconClock`, `text-orange-600` | `Pending` |
| Confirmed | White, as now | `IconCircleCheck`, `text-green-600` | `Confirmed`, `text-green-700` |
| Rejected | White, `opacity-60` on the whole card | `IconCircleX`, `text-neutral-500` | `Rejected` |
| Voided by Admin | White, `opacity-60` on the whole card | `IconBan`, `text-neutral-500` | `Voided by Admin` |

The icon is decorative (`aria-hidden`). The label carries the meaning, so colour is never the only signal.

### Waiting for you

- Each Match uses the Match card (Pending style) with **Reject** and **Confirm**. Drop the single divided list.
- Below the section, an `<hr className="border-neutral-200" />` separates it from the tab content. This is the same divider Home uses below its forms. It renders only when the section does.
- `listMatchesWaitingForMe` stops reading the full Match list. It selects only `status = 'pending'` Matches for the Ladder, so a Pending Match older than the loaded page still shows up.

### Matches tab: load more

- Add a paged read to `src/data/match.ts` that returns one page of Matches plus the Ladder's total Match count. Order by `recorded_at desc, id desc` so pages are stable. Keep `listMatches` as it is, because the integration tests use it.
- `MatchHistory` uses `useInfiniteQuery` with page size 10, under query key `['matches', ladderId, 'pages']`. Existing invalidations of `['matches', ladderId]` then still refresh it. Drop duplicate ids when joining pages, in case a Match was recorded between loads.
- Below the list:
  - `Showing 10 of 34 Matches` (`text-sm text-neutral-600`, centred).
  - A full-width load-more button using food-friends' copy: `Load next 10` or `Load last 4`, and `Loading…` while fetching. Hide it once everything is loaded.
  - When everything fits on one page, show only `Showing 3 of 3 Matches`.
- The **Matches** tab count (`· 34`) comes from that total, not from a full fetch. Replace the route's `listMatches` query with a count-only query (`head: true`, `count: 'exact'`) under `['matches', ladderId, 'count']`.
- First load keeps its current loading text. Background refetch shows nothing new.
